Baseline: the environment before we touched it

What stock LibreChat looks like when you follow its quick start, and what that would mean in production.

How we ran the baseline

Date, machine (laptop OS, RAM), LibreChat version/commit. We cloned the upstream repository and ran its default docker compose up with the example .env, then connected a Gemini key.

Screenshot of stock LibreChat running locally (same image as on the System page is fine) plus docker compose ps output.

What we found (from the upstream docker-compose.yml and .env.example)

AreaStock behaviourRisk in production
DatabaseMongoDB started with mongod --noauthAnyone who can reach the port can read or delete every conversation
SecretsAPI keys, JWT and encryption secrets in a plain .env file next to the codeEasy to commit to Git or leak in a screenshot
Extra servicesMeilisearch, pgvector and a RAG API container; pgvector with a hard-coded example passwordMore memory, more attack surface, more to patch
NetworkApp port published on the host, plain HTTPPasswords and chats travel unencrypted
BackupsNoneA disk failure loses all users and conversations
Monitoring and alertsContainer logs on the local disk only; no metrics, alarms or dashboardNobody notices an outage; logs can fill the disk
Access and auditWhoever has the laptop is admin; open registrationNo accountability, anyone can sign up and use the quota
Cost controlNoneA loop or abuse can run up a model bill unnoticed
